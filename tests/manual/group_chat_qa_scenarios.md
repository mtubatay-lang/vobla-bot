# Ручные сценарии: ответ бота на вопросы в групповом чате (RAG)

Чек-лист для проверки функции ответа на вопросы в группе. Один вопрос — одно сообщение; после каждого ждём ответ бота (или отсутствие ответа) и фиксируем результат.

## Порядок прогона

1. Чат для тестов: группа «Тест группа», entity в MCP Telegram = **`"3377597100"`**.
2. По одному сообщению: отправить вопрос через MCP Telegram `send_message` (entity: `"3377597100"`).
3. Подождать 15–20 секунд.
4. Вызвать `get_messages` (entity: `"3377597100"`, limit: 8–10) — проверить, есть ли ответ бота после вашего сообщения.
5. При необходимости запросить логи Railway (`get-logs`, deploy, service vobla-bot, lines 50–100), отфильтровать по `[GROUP_CHAT_QA]`, `rag_pipeline`, `kb_search_performed` — зафиксировать outcome, top_score.
6. Заполнить колонку «Факт» и «Примечание» в таблице ниже.

## План улучшений после теста

Заполнить после прогона на основе таблицы и логов.

### Классификация «это вопрос» (_is_question)

- [ ] Бот молчит на формулировки «Регламент по открытию» / «Нужна информация когда…» → дообучить промпт (ещё примеры в system/user).
- [ ] Бот отвечает на «Привет» / «Готово» → ужесточить промпт (явные исключения, примеры «не вопрос»).

### Пороги RAG

- [ ] В логах много no_answer_silent при top_score 0.38–0.44 → рассмотреть снижение MIN_TOP_SCORE_FOR_ANSWER (env 0.40–0.42).
- [ ] Во всех ветках no_answer_silent в метрики уходит top_score (и reason) — проверено.

### Короткие запросы по теме

- [ ] «Регламент по открытию магазина» распознаётся как вопрос, но RAG не находит / низкий score → проверить чанки в Qdrant, расширение запроса для коротких фраз.

### Голосовые и фото

- [ ] Добавить 1–2 ручных кейса: голосовое с вопросом → ответ бота.
- [ ] Один кейс: фото с подписью-вопросом → ответ; фото без подписи → не ответ (уже в коде).

### Метрики и обратная связь

- [ ] Регулярно выгружать из логов rag_pipeline / kb_search_performed, смотреть outcome и top_score.
- [ ] Опционально: кнопки «Помогло» / «Не помогло» под ответом бота.
