## Краткий отчёт по нововведениям и изменениям

### 1. RAG и база знаний
- **Нарезка по разделам:** `document_structure_parser`, `structure_aware_chunk_text` с метаданными `section_path`, `section_id`, `section_title`, `chunk_id` (формат VB_REG_NN_KK). Передача этих полей в Qdrant.
- **Предподготовка документов:** модуль `document_preparation` — FAQ из CSV и регламент из TXT/PDF/DOCX/MD в RAG-ready MD. Интеграция в `/kb_add` для всех форматов; поддержка загрузки CSV.
- **Скрипты и данные:** `prepare_regulation_for_rag.py`, `prepare_faq_csv_for_rag.py`; файлы `knowledge_rag_ready.md`, `faq_franchise_rag_ready.md`.
- **Эксперименты (откат):** HyDE/BM25 по умолчанию, «ответ как весь документ», LLM-сборка ответа из всех чанков после rerank — закоммичены и откатаны в тот же день. Оставлены: cross-encoder reranker, BM25/HyDE сервисы, golden set, скрипт оценки.

### 2. QA-режим и уточнения
- **Лимит уточнений:** `MAX_CLARIFICATION_ROUNDS` (1, затем 0) — ограничение раундов уточняющих вопросов в личном и групповом чате.
- **LLM-классификация:** различение «ответ на уточнение» / «новый вопрос» / «follow_up»; в группе — «ответ на уточнение vs новый вопрос» при pending_clarification.
- **Поиск по вопросу:** в группе поиск только по текущему вопросу; «другой вопрос» — поиск по предыдущему; усиленные промпты для new_question vs follow_up.
- **Короткие ответы:** ответы вида «1», «2», «3» при уточнении считаются ответом на уточнение.

### 3. Full-file контекст (режим «весь документ»)
- Режим QA с подстановкой одного PDF/txt в контекст LLM вместо RAG; конфиг и папка `data`; сервис `full_file_context`.
- В этом режиме — без проверки контекста и без уточняющих вопросов до поиска.

### 4. Рассылка (Broadcast)
- В превью рассылки — выбор: отправить оригинальный или улучшенный (LLM) текст.

### 5. Сбор получателей рассылки
