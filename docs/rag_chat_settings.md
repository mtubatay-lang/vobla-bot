# RAG в групповых чатах: настройки

## В каком чате отвечает бот

Ответы на вопросы по базе знаний (RAG) в групповых чатах обрабатываются только в разрешённом чате (или во всех, если ограничение отключено).

- **`RAG_TEST_CHAT_ID`** (переменная окружения):
  - **Не задана** — используется чат по умолчанию (значение из кода, тестовый чат).
  - **Пустая строка** — RAG отвечает **во всех** групповых чатах, где есть бот.
  - **Число** (ID чата) — бот отвечает на вопросы по RAG **только в этом чате**; в остальных группах RAG не срабатывает.

Удобно задать пустую строку для продакшена («отвечать везде») или один ID для теста в одной группе.

## Дополнительные опции

- **`RAG_SEND_NO_ANSWER_REPLY`** — при значении `true`, если бот не нашёл ответ в базе, он отправит в чат короткое сообщение: «Пока не нашёл ответ в базе. Менеджер может ответить позже.» По умолчанию `false` (бот молчит, вопрос попадает в очередь для ответа менеджером и предложения записать в базу).

- **`MIN_TOP_SCORE_FOR_ANSWER`** — минимальный score лучшего чанка для ответа в группе (по умолчанию `0.45`). Ниже этого порога бот не отвечает (молчит или шлёт no-answer reply, если включён `RAG_SEND_NO_ANSWER_REPLY`).

## Мониторинг

В логах сервиса ищутся события `rag_pipeline`, `kb_search_performed`, `kb_answer_generated`. В `rag_pipeline` при outcome `no_answer_silent` передаётся `top_score` (и при необходимости `reason`), чтобы анализировать, из‑за чего бот не ответил (низкий score, недостаточно данных, grounding и т.д.).
